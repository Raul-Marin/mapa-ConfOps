# Fuentes, conectores y grado de delegación

[← Volver al inicio](../README.md)

Puedes empezar aportando notas, ejemplos de entregas y observaciones del equipo. Los conectores son opcionales.

## Qué puede alimentar el mapa

| Fuente | Qué puede aportar | Qué conviene conservar |
| --- | --- | --- |
| Dificultades del equipo | Situaciones que merecen explorarse. | Un ejemplo y su contexto. |
| Observación del trabajo | Dónde aparece una duda, espera o retrabajo. | Tarea, momento y límites de la observación. |
| Comunidad | Una idea o práctica que podría probarse. | Procedencia y por qué parece relevante. |
| Pruebas anteriores | Evidencias y preguntas que siguen abiertas. | Mapa previo, criterios y decisión. |
| Jira, Slack, Notion u otras herramientas | Fragmentos concretos del trabajo, si hay acceso. | Referencia y periodo consultado. |

Un ticket o un mensaje es una señal contextual. No permite atribuir culpa ni medir el rendimiento individual.

## Primer paso: contexto manual

```text
Estas son tres notas de nuestras revisiones.
Identifica dificultades observadas y separa hechos de interpretaciones.
Propón una exploración pequeña. Conserva las referencias de cada nota.
No uses otros documentos ni asumas que estos ejemplos representan todo el trabajo.
```

## Segundo paso: lectura delimitada con un conector

Si la herramienta ya tiene acceso y puedes utilizarlo para la tarea, especifica el alcance:

```text
Consulta solo [proyecto, canal o documento] durante [periodo].
Busca ejemplos de [dificultad].
Recoge la referencia de cada observación y prepara una propuesta de mapa.
No publiques mensajes ni modifiques tareas.
```

El paquete no configura servicios ni incluye claves. Si no hay acceso, el asistente debe indicarlo y trabajar con el material que puedas aportar.

## Qué delega esta versión

| Acción | Comportamiento |
| --- | --- |
| Preparar un mapa | A petición del equipo, con contexto disponible. |
| Revisar evidencias | A petición del equipo, recuperando el mapa anterior. |
| Elegir seguir, ajustar o parar | El agente recomienda; el equipo decide. |
| Guardar una revisión en Cursor | El asistente principal puede hacerlo cuando se pide. El subagente devuelve texto. |
| Consultar una fuente externa | Solo si existe acceso y se delimita la tarea. |
| Crear tareas, enviar mensajes o programar seguimientos | No forma parte de la configuración incluida. |

Una definición de agente y una skill no son, por sí solas, un sistema de seguimiento autónomo. Para delegar acciones posteriores harían falta herramientas configuradas, un alcance acordado, límites y una forma de revisar sus resultados.

## Al compartir el recurso

La carpeta `ejemplos/` contiene un caso ficticio publicable. Los mapas de tu equipo pueden incluir información interna: guarda cada mapa en el lugar que corresponda a vuestro trabajo y comparte únicamente el contexto necesario.
